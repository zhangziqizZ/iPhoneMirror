## 短版（视频简介 / 动态 / 一句话）

**在鸿蒙电脑上投屏 iPhone。**

iPhoneMirror 鸿蒙版是开源项目 [iPhoneMirror](https://github.com/RayrenSX/iPhoneMirror)（Windows 版）的
鸿蒙 PC 移植：把上游的协议栈与采集状态机整棵搬过来，只为鸿蒙补一层平台实现。
USB 有线采集与 AirPlay 无线接收同在一套界面里，低延迟、不经过任何云端中转。

本项目同样是开源软件（GPL-3.0），完整源码公开，欢迎试玩与提 Issue。

---

## 一、这是什么

**iPhoneMirror 鸿蒙版 = 把 Windows 上的 iPhone 投屏工具，按「平台后端替换」的方式移植到鸿蒙 PC（HarmonyOS 2in1）。**

它不是"照着重做一个投屏应用"。上游 iPhoneMirror 的 C++ 核心（Apple 私有 USB 协议、
QuickTime/CoreMedia 解析、H.264 解码、采集状态机、解码帧模型）被**逐字节搬入本工程**，
鸿蒙所需的一切都写成**新增平台层**：USB DDK 传输、AVCodec 解码、OHAudio 播放、
EGL/GLES 预览渲染、自研 mDNS 应答器。

这套手法不是我们发明的——上游作者自己就这么做过一个 Linux 分支。
本移植沿用同一套分层与同一条纪律：

> **对上游既有文件只允许做接口抽取，不允许夹带行为变更；平台相关一律新增文件。**

因此本工程里 `cpp/Core/` 与上游 `src/Core/` 保持零差异，可以直接逐字节比对验证。

界面部分无法照样搬：上游 UI 是 WPF（.NET），鸿蒙没有 .NET 运行时。
本移植选择**按上游 `MainWindow.xaml` 逐控件还原**成 ArkTS，而不是另做一个"极简壳"——
图标与配色这两层更是原样搬过来（Fluent 图标的 SVG 坐标一个不改，深色主题的色值一个不改）。

| 状态与诊断 | ✅ | 采集状态机可视化、USB/环境自检、解码与渲染链路逐分支诊断 |
| 后台保活 | ✅ | 切到后台继续接收（长时任务声明） |
| 深色主题 / 图标 | ✅ | 与 Windows 版一致的配色与 Fluent 图标 |
| 蓝牙反控鼠标（BLE HID） | 🧪 | GATT 服务、BLE 广播、HID Report 投递链路已实现且可在状态行读到真值；但 **iPhone 侧指针显示尚未成功，不保证可用** —— 见「已知技术限制」 |

### 画质与延迟取向

与本项目的一贯取舍一致：**不做云端中转**，USB 场景不依赖网络，
无线场景只在局域网内直连；预览走硬件解码 + GPU 上屏，不做二次编码。

## 三、还不支持什么（诚实清单）

以下能力**目前没有实现**，界面上会明确灰化并提示，不会假装可用：

- ⛔ **反向控制里的「多指触控 / 绝对定位」**——上游的 USB CoreDevice 触控隧道
  （`tools/usb_touch_bridge.py`，走 usbmux + CoreDevice + 开发者磁盘镜像）能做到
  「鼠标在哪就点哪」，那条路鸿蒙侧尚未开始。**能做的是蓝牙这条**：真 BLE HID
  外设（HOGP），鼠标放到画面上直接操控、移开即释放；受 iOS 辅助触控的限制，
  上限是**单指指针 + 键盘**，且 iOS 侧需要一次性设置（见下面的已知限制）。
  ★ 注意：蓝牙这条**目前是 🧪 实验性**的 —— 链路已实现，但 iPhone 侧指针显示
  尚未成功，**不保证可用**（见下）。界面上这一项带「（实验）」标识。
- ⛔ **录制与推流 / 虚拟摄像头**（上游走 Media Foundation / FFmpeg 管线）
- ⛔ **截图保存与分享界面**（解码帧已可取，界面未接）
- ⛔ **全屏预览**
- ⛔ **多设备同时投屏**（上游支持每台设备独立会话、独立窗口）
- ⛔ **快捷键后端**

### 已知技术限制

- **蓝牙反控（BLE HID 鼠标）仍在实现阶段，不保证可用**：GATT 服务、BLE 广播、
  HID Report Map 与投递链路都已实现，状态行能读到真实读数（主机读/写/订阅、应答
  次数、已配对台数）；但 **iPhone 侧至今可能完全不出现指针**（iOS 能发现本机、
  能配对成功，却不建立 HID 设备）。这是当前**已知情况**，界面上这一项带「（实验）」
  标识，反馈欢迎、但**没有可用性承诺**。
- iOS 的屏幕采集与 AirPlay 都是 **Apple 私有协议**，未来 iOS 更新可能需要适配。
- 无线接收需要电脑与 iPhone 在同一局域网；USB 场景需要系统允许应用接管该 USB 设备。
- **反向控制需要 iPhone 侧一次性设置**：打开「设置 → 辅助功能 → 触控 → 辅助触控」，
  再在蓝牙里与本机配对。这一步是 iOS 对外部指针设备的硬性要求，应用无法代劳；
  做完之后就是「鼠标放到画面上即操控」，不必再有任何前置动作。
- 蓝牙反控是**相对指针**（iOS 的蓝牙鼠标只接受相对位移），因此 iPhone 上的指针
  位置与电脑光标位置不保证一一对应 —— 这是该通道的固有性质，不是本移植的缺陷。
- 当前为**开发者预览版**，接口与行为仍会变动。

## 四、运行环境

| 项 | 要求 |
|---|---|
| 设备 | 鸿蒙 PC（HarmonyOS 2in1） |
| 系统 | HarmonyOS 6.1.0（API 23）及以上 |
| 构建 | DevEco Studio + HarmonyOS SDK；原生层用 NDK clang 交叉编译 |
| 签名 | 使用自带调试签名即可安装到自己设备（正式分发需自行配置签名） |

> 本工程目前**不发布预编译安装包**，请从源码构建；构建方式见仓库内
> `docs/移植说明.md`（含每一层"哪些是上游原封不动的代码、哪些是本移植新增的"）。

### 5.4 只链接系统库，不捆绑任何第三方二进制

鸿蒙版的所有平台后端只链接随系统提供的 NDK 库，**不再分发任何第三方二进制**：
`libusb_ndk.z.so`（USB DDK）、`libnative_media_vdec` / `codecbase` / `core`（AVCodec）、
`libohaudio.so`（OHAudio）、`libnative_window.so` 与 `libEGL.so` / `libGLESv3.so`（图形）。

### 5.5 明确说明：上游用到、但鸿蒙版**没有**使用的东西

为避免误解，这里反向声明一次——以下组件在上游 Windows 版中存在，
**鸿蒙移植版不包含、不链接、不打包**：

- **libusb / libusb-win32**：鸿蒙改用系统 USB DDK，不链接 libusb
- **FFmpeg**：鸿蒙改用系统 AVCodec，本工程不捆绑 FFmpeg
- **WPF-UI / Avalonia / Markdig / Inno Setup**：均为上游 Windows/Linux 界面与安装器依赖
- **Apple 的任何软件与二进制**：不包含 AppleMobileDeviceSupport、Apple 驱动或 iTunes 组件
